# 本地库存台 · Inventory Desk

为小型跨境电商卖家准备的离线商品库存工具。中文界面，无需安装运行环境、注册账号或连接网络。完整解压后，用现代浏览器打开 `index.html` 即可使用。

## 功能

- **商品登记**：SKU、名称、库位、初始库存、低库存预警线、人民币参考单价。
- **出入库**：记录数量及备注；出库超过当前库存时阻止提交。
- **盘点**：输入实际剩余数量，自动记录与账面库存的差额。
- **低库存提醒**：每个商品独立设置预警线，支持低库存和缺货筛选。
- **操作流水**：保留初始库存、入库、出库、盘点，支持按商品筛选和分页。
- **搜索与概览**：按 SKU、名称、库位搜索，显示总商品数、总件数、估值及需关注商品数。
- **本机保存**：每次修改尝试自动保存到当前浏览器，不使用服务器。
- **导出与恢复**：完整 JSON 备份可恢复；库存 CSV 与流水 CSV 便于用 Excel 查看。

## 第一次使用

1. 完整解压 ZIP，进入 `inventory-desk` 文件夹。不要在压缩包预览里直接运行。
2. 用现代 Edge、Chrome、Firefox 或 Safari 打开 `index.html`。
3. 点击“新建商品”。为每种商品规格设置一个唯一 SKU，例如 `BAG-BEIGE-S`。
4. 填写实际初始库存、预警线及参考单价。单价统一为人民币，未知可填 `0`。
5. 商品到货时记录“入库”，发货时记录“出库”。清点仓库时选择“盘点”，填写**实际剩余数量**，不是差额。
6. 在库存表查看状态，按需筛选需补货商品。库存等于预警线时也会提醒，库存为 `0` 时显示“缺货”。
7. 重要操作完成后，点击“导出 JSON 备份”，把备份保存在自己的安全位置。

**首次建议先导出一份空账本 JSON，再载入演示数据。** 试用结束后恢复这份空账本，就可以开始登记自己的真实商品。演示只允许在空账本中载入，包含虚构商品及当天创建的初始库存流水，没有虚构的历史业务记录。

## 三种库存操作的区别

| 当前库存 | 操作 | 填写数量 | 操作后库存 | 流水变动 |
| ---: | --- | ---: | ---: | ---: |
| 20 | 入库 | 5 | 25 | +5 |
| 20 | 出库 | 3 | 17 | -3 |
| 20 | 盘点 | 18 | 18 | -2 |

盘点数量与当前库存相同则不新增流水。不能用负数“反向操作”。误操作可用相反方向的出入库或重新盘点来纠正，并在备注说明原因。

编辑商品信息不会修改当前库存。为保留可核对的流水，本版本不提供单独删除商品或流水的功能。停止销售的商品可保留为零库存；需要全新空账本时，可恢复自己预先导出的空账本备份，恢复前先备份旧账本。

## 汇总和估值口径

- 商品总数按不同 SKU 统计；同一商品的不同规格应分别建档。SKU 去除首尾空格后比较，**不区分英文字母大小写**。
- 库存单位为整数“件”，不支持小数重量、长度等单位。
- 库存总件数为所有商品当前库存相加。
- 需关注商品数为“当前库存 ≤ 该商品预警线”的商品数，包含零库存商品。
- 库存成本估值 = 各商品当前库存 × 该商品当前人民币参考单价，再求和。
- 单价最多两位小数，内部使用整数“分”保存；编辑单价会改变当前估值，不会改写历史采购金额。
- 这是单一库存池，库位只是文本备注，不代表独立的仓库余额。
- 商品名称、SKU 与库位可以修改，旧流水会显示商品**当前**名称及 SKU，不保留商品信息的历史快照。
- 流水按记录顺序展示，最近录入在前。页面时间使用本机时区，CSV 流水时间使用 ISO UTC 格式；改变系统时钟不会重新排序已有记录。
- 这不是订单、利润、税务或完整会计系统，也不提供先进先出和移动加权成本核算。

## 保存、备份与换设备

每次商品和库存修改会尝试写入当前浏览器的 `localStorage`，键为 `inventory-desk:v1`。页面会明确提示是否保存成功。

**本机保存不是云端备份。** 隐私模式、清理浏览器数据、更换浏览器、移动 HTML 文件或换设备都可能导致无法读取原数据。各浏览器对 `file://` 本地文件的存储策略有所不同。

- 保存失败时，工具仍可在当前页面使用，但关闭或刷新可能丢失修改。此时请立即导出 JSON。
- 如果已有本机数据损坏或无法读取，工具进入临时空库存模式，不自动覆盖原数据。可以导入有效 JSON 备份恢复；临时模式新增的数据也可导出。
- 不要在多个窗口同时操作。若检测到其他窗口修改同一份本机数据，本窗口会暂停接受新记录，提示刷新核对。它不是支持多人协同的系统。
- 如需换设备：旧设备导出 JSON → 把文件私下传到新设备 → 在新设备打开工具 → 点击“恢复 JSON 备份”。

恢复时先校验版本、SKU 唯一性、商品关联、流水前后库存及数量范围，再显示待恢复商品和流水数量。**只有点击“确认替换并恢复”才会替换当前全部数据；不合并账本。** 恢复前先导出当前 JSON。校验失败的文件不会导入，也不会修改当前库存。

CSV 是查看用的报表，不能恢复数据。两个 CSV 按钮始终导出**全部商品或全部流水**，不受页面搜索、筛选或分页影响。CSV 使用带 BOM 的 UTF-8 编码；对以 `= + - @` 开头的文本添加英文单引号，降低表格软件把文本当作公式执行的风险。数字型变动数量保留为数字。

## 数据范围

这是轻量个人工具，每个账本最多 1,000 个商品、10,000 条流水，单个商品库存和预警线为 0 至 1,000,000 件，参考单价为 0 至 10,000.00 CNY。SKU 最多 50 字符，名称 100 字符，库位 60 字符，备注 160 字符。备份导入上限 10 MiB。

接近流水上限时请先导出备份，再评估迁移到更完整的库存系统。浏览器也有自己的存储额度，可能在条数上限之前保存失败；以页面提示为准。

## 上传 GitHub，无需命令行

建议仓库名：`inventory-desk`。可复制的仓库简介：

> Offline inventory manager for small sellers, with stock movements, low-stock alerts, CSV export and JSON backups.

1. 在自己的 GitHub 创建一个空仓库。名称可自行修改，公开或私有按需要选择；本包已含说明和许可证，不必重复生成。
2. 解压 ZIP，进入 `inventory-desk` 文件夹，选择里面全部 6 个文件，包括 `.gitignore`。
3. 通过仓库的文件上传入口上传这些文件；已有文件的仓库通常是 `Add file` → `Upload files`，空仓库也有上传现有文件的入口。
4. 根目录应直接包含 `index.html`、`README.md`、`LICENSE`、`.gitignore`、`CHANGELOG.md` 和 `CHECKLIST.md`。不要只上传 ZIP，也不要多套一层文件夹。
5. 填写符合实际的提交说明，例如“添加离线库存管理工具初版”，按页面提示提交。

页面文字会随语言和仓库状态不同，可参考 [GitHub 官方上传指南](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository)。普通 GitHub 代码页面不会直接运行 HTML；使用时下载并在本机打开即可。

公开仓库只上传工具源码和说明。**不要上传真实库存 JSON、CSV、订单、客户信息或账号凭证。** `.gitignore` 不能阻止网页手动上传，也不能撤回已经公开的数据。

## 真实维护建议

- 先用一件真实商品核对初始库存，再记录实际发生的出入库。
- 用脱敏例子记录遇到的问题，例如“盘点数量输入错误时提示不清楚”。
- 按真实需求改善说明、增加分类或优化搜索；修改后按 `CHECKLIST.md` 核对。
- 在 `CHANGELOG.md` 记录实际完成的改进，不为凑次数制造提交。

没有刷星、自动空提交或伪造历史贡献功能，正常维护本项目不保证通过 Telnyx 或其他第三方账号验证。
